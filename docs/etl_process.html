ETL Process — PDF to Viewer

How the Taipei urban-renewal gazette (核定案件一覽表) becomes viewer/projects.data.js and the static HTML viewer. Prose source of truth: docs/etl_process.md · Companion pages: domain model · release-diff report. Measured on the 2026-10-28 gazette: 1,444 records → 680 projects, 2002-03-21 → 2026-10-28.

關於

1Pipeline overview

One command runs the whole flow: python -m urtpe.cli source.pdf -o data --viewer viewer --links. Stages 2–7 run inside the single-writer lock; every gate (§6) evaluates before the first artifact is written.

1
Acquirescripts/poll_gazette.py
Hash-gated check of the publisher page. Downloads the ~2 MB PDF only when the page's bytes change; archives it outside the repo. → urtpe-gazettes/核定案件-YYYY-MM-DD.pdf + index.jsonl
2
Extracturtpe/extract.py
Ruled-table read via pymupdf find_tables("lines"). Verbatim cells, dual calendar → ISO, publisher truncation excluded and named. → data/raw.tsv (RawRecord)
3
Cleanseurtpe/cleanse.py
Known-error normalization, derived fields (section, parcels, aliases, stage, track), ambiguity → review flags. → data/clean.tsv (CleanRecord)
4
Ledgerurtpe/ledger.py
Append-only manual corrections, keyed on land core + approval date, applied on every ingest. → corrected CleanRecords (4 entries live)
5
Mergeurtpe/merge.py
Weighted similarity (§4) clusters repeat approvals of the same 更新單元 into families; anchor + project_id per family. → data/merged.tsv (Project)
6
Linksurtpe/links.py
Cache-first portal discovery (Taipei ashx + national portal), --links, onto the merged families. → data/.link_cache/, crawl_log.tsv
7
Graphurtpe/graph.py
Per-project history: nodes = records, edges = revision / track / section chains converging on the anchor. Schema v2. → data/projects.json
8
Viewerurtpe/viewer.py
The payload window.PROJECTS = {…} for the static file:// page, plus the ?v= cache-bust on both script tags. → viewer/projects.data.js
↺  Loopback: viewer/projects.data.js is both input and output — --from-js reloads it and re-emits it, so the payload is state, not scratch.
Full ingest
python -m urtpe.cli -o data --viewer viewer --links
Stages 1–8, from the PDF. ~45 s; the only way a reader change reaches historical records uniformly.
Rebuild
python -m urtpe.cli --from-js viewer/projects.data.js -o data --viewer viewer --links
Skips stages 2–5: nodes load back as CleanRecords verbatim; links → graph → viewer only.

2Acquire — hash decides, timestamp never does

scripts/poll_gazette.py answers one question: has the city published a gazette we do not hold? It archives; it never ingests. Ingesting is a separate explicit act.

PropertyRuleWhy
Change detectionSHA-256 content hash The publisher re-uploads unchanged documents under a later 資料更新 stamp (measured 2026-10-05); a timestamp poller would re-ingest weekly.
Steady-state costone ~86 KB page GET The ~2 MB PDF downloads only when the page's bytes change.
Every check leaves a recordpoll_log.jsonl: new_gazette / reuploaded / unchanged / failed A check that found nothing must not look like a check that never ran.
Archive locationD:\project\urtpe-gazettes\ (outside git; URTPE_ARCHIVE_ROOT override) Corpus completion, reconciliation and the release-diff report all re-read archived PDFs; members are never deleted.
PDF linkslive link repoints; version-specific URL durable The archive index records each publication's publisher_url.

3Extract — refuse rather than approximate

pymupdf reads each page with find_tables(strategy="lines"); cell boundaries come from the document's own ruling lines, never stored coordinates. Seven columns verbatim: 編號, 核定日期, 行政區, 案名, 地號, 實施者, 更新規劃單位 — plus gazette_id. A structure the reader cannot read exactly raises TableStructureError (exit 3); nothing is written.

3.1 The two-fault distinction on a 地號 cell

Reader fault — page furniture
The city prints the page number inside the last row's 地號 cell.
✓ Stripped — only when the trailing digits equal that page (strip_page_footer).
Publisher fault — truncation
The city cuts the cell at the printed row height and never draws the remainder; the text is absent from the PDF.
✗ Excluded and named — never repaired by inference.

A cell is publisher-truncated when it ends in a tail pattern (、，, / digit / sub-parcel hyphen) or lost its closing phrase while showing fewer parcels than its 案名 declares. A completed closing phrase (地號等N筆土地) is never count-checked — 48 rows per Gregorian gazette disagree with their 案名 and are complete as published.

3.2 Two bounded repairs, both audited

RepairTriggerConditions (all must hold)
Corpus completion
complete_truncated_cell		 default, on every ingest same 段/小段 · truncated text is a literal prefix of the candidate's · candidate's parcel count equals the count the 案名 declares
API recovery
--recover-truncated		 opt-in flag only; without it output is byte-identical same unit · surviving 案名 contained · declared count present · date closes (±1 day flagged). Residuals rejoin the exclusion path.

Calendars: ROC through the 2026-08-27 gazette, Gregorian from 2026-09-24 onward; accepted per cell, normalized to ISO-8601. published_date comes from the document's own 統計至 line.

~70% of records are repeat stage approvals of the same 更新單元. score(r1, r2) in [0,1], urtpe/merge.py:40:

< 0.5 separate units 0.5–0.7 borderline — flagged for review ≥ 0.7 same family (LINK_THRESHOLD) ledger confirm_merge unions before scoring, whatever the score

Anchor: newest 核定日期, tie-break to lowest recno — the family's 現況 record. project_id is the anchor's land-core slug ({district}-{section}-{first_parcel}地號等{count}筆); it churns (~11% of multi-record families have moved) and is not a stable identity. The census gate then proves the partition total and disjoint.

5Links — the durable cache, not the network, is the state

urtpe/links.py (4,450 lines, both portal adapters) runs cache-first: a result.json hit means zero HTTP calls for that project. --links is recommended and advisory by design (D5).

StepSourceYields
1 · Cache check data/.link_cache//result.json (~727 project dirs) previous DiscoveryResult — no network
2 · Taipei platform Get_updcase_list.ashx by section + first parcel, then Get_project168_second.ashx per case_id case ids, the 34-field milestone map, implementation, rewards
3 · National portal portal_index.json (newest ~110, WAF-capped) → view/N page 推動歷程 milestones, twur_url; strict matcher on section+parcel+count
4 · Status per project resolved / resolved_no_city / unresolved / error → crawl_log.tsv
Cache safety
The cache is durable state: project_aliases.json migrates dirs across project_id churn; the coverage guard aborts before emission when a coverage flag drops or every identity re-keys — the 2026-08-24 shape, where four concurrent runs wiped 47 caches. The single-writer lock (§6) exists because of it.

6Gates — ordered, before any artifact is written

A check that runs after the damage is not a check. Every gate evaluates before the first write, so a refused ingestion leaves every artifact exactly as it was.

OrderGateModuleOutcome
pre-read single-writer lock — one run per output tree; stale after 6 h or a dead PID urtpe/lock.pyexit 5
after read structural faults — merged cell, ragged grid, page with no table urtpe/extract.pyexit 3
after read completeness tripwire — 編號 contiguity (minus explained exclusions), unparsed dates, pages yielding no table urtpe/tripwire.py:38exit 4
after merge census partition — total, disjoint, members sum to the record count urtpe/tripwire.py:202exit 4
after merge reconciliation vs. the archived predecessor — three authoritative signals only; blocking on shrink, withdrawn newest cohort, total re-key urtpe/reconcile.pyexit 2
on emission emission-fault check — link/implementation data wholly absent; badge/flag disagreement urtpe/emission.pywarning only

6.1 Exit codes are a contract

CodeMeaningState on disk
0successwritten
2unexplained reconcile changes (--allow-reconcile-block not given) archive/index written, emission not written
3TableStructureError — reader refused the document nothing written
4TripwireFailure (incl. the census gate)nothing written
5LockHeld — another run owns this output treenothing written
1anything elsenot a contract — diagnose before retrying
A non-zero exit is a refusal, not a flake
Do not retry past it and do not pass a flag to get around it. --allow-reconcile-block is marked 危險 and --no-archive 不建議 in the help text for a reason.

Cache-bust and publishing
write_projects_js rewrites the ?v= on both script tags from the dataset (publication date + 4-hex digest of date-and-counts); identical data yields an identical version. The site publishes to https://happypig.github.io/urTPE from main — a commit touching viewer/ leaves the live site stale until pushed (python scripts/check_deploy.py reports fresh / stale / missing). Render-path regression check: node scripts/viewer_smoke.js (manual, not pytest).

9Operating the pipeline

Full ingest of a new gazette:

1.Run python scripts/poll_gazette.py — it archives on new_gazette.
2.Ingest: python -m urtpe.cli "D:\project\urtpe-gazettes\核定案件-YYYY-MM-DD.pdf" -o data --viewer viewer --links
3.Read the run output — tripwire PASS, reconcile, ledger, exclusion count. Any [CENSUS]/[EMISSION] line names a real defect.
4.Exit 0 commits the dataset (mind the ~24 MB diff). Exit 2/3/4/5 is a refusal — diagnose, never bypass with a flag.
5.Push main so Pages serves the new payload; verify with python scripts/check_deploy.py.
Rules that outlast any single run
One run per output tree (the lock is stale after 6 h or a dead PID — check the PID before deleting it) · never key anything durable on 編號 · manual corrections go in the ledger, not a dated script · data/.link_cache/ is durable state — five backup dirs from past incidents exist because it was once lost · tests: python -m pytest (1,231 collected; one deliberate skip at tests/test_idempotent_flags.py:117).
