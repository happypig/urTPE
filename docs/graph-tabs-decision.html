§1b2026-10-26 → 11-01 的變更帶進 TAB 2 設計的新事實

決策文件初版之後，四個 openspec 變更落地歸檔（restore-2026-09-24-gazette、 land-core-slug-fallback、wire-standing-checks、 viewer-stage-chip-coverage），另有 recover-truncated-rows-via-api 與 check-declared-parcel-counts。對 TAB 2 設計有直接影響的是以下五件。

節點從兩態變三態 recovered

實心＝gazette 核定、虛線＝有案無核定之外， 現在有第三種：gazette 有印但儲存格被截斷，由市府 API 補全（4 筆：188、1005、1131、1206， 全帶 partial，1005 另帶 ambiguous-zone）。 TAB 2 的圖例必須多一種記號，且使用者必須看得出差異。

join 已落地，兩個決定已做 Wave 5

recovery.cases 有兩種 id 拼法 （R-form R089213-02 vs 數字 10403071，同一案）； normalise_case_id 以唯讀方式正規化，儲存欄位保持原樣。 當 recovery 與 discovery 候選不一致（1005：recovery 選 09610235/09610236， links.taipei 是 09610231），recovery 綁定勝出。 TAB 2 的跨泳道邊必須走同一個 join。

泳道成員有兩個來源 不是一個解析器

虛擬案自帶 track 欄位 （973 筆，值就是四個泳道名）；紀錄沒有，要從 name_raw 解析 （1,442 筆中 533/522/356/20）。stage_事業計畫/stage_權利變換 不是泳道欄位——只有 533 筆雙軌紀錄有值。10 筆舊制「都市更新計畫」案名 TRACK_ORDER 已有既有泳道；1 筆出版錯字（事業換計畫）落入其他。

另外兩件，改變的是輸入品質而非形狀

declared_count 可信但只部分被強制 — counter 修正後計算可靠，但 check 只跑在「失去收尾語」的儲存格上；收尾語在的細格一律不做數量檢查 （每個西元公報有 48 列與自身案名不符但屬完整出版）。判別式可以用它，但不能當成已驗證值。 錨定比初版量測時好 — 歧義標記從 456 降到 342，因為 implementation 精確比對的來源鏈 （implementation > milestones_source > national-only）解析掉了大部分；但 anchoredByCase 仍是後寫蓋前寫，規則本身還沒換。

§2剩下的唯一一個決策

§6尚未解決、需要人決定的

1 · TAB 1 是產品還是基準. §2 — 自初版未決；2a/3a 是否進 TAB 1 由它決定。

2 · 無法定位的標記. 225 個源案不落在該單元任何一筆紀錄上， 22 個在標記日期之前沒有任何核定。這些標記應保持「無泳道」並據實標示， 而不是被硬塞進某一條泳道。

3 · 30 筆沒有案件的紀錄. 真實核定但無 Taipei 案 — 獨立細泳道，或併入 track 泳道但不連 case 邊。

4 · twur 錨定. 使用核發日期來自全國門戶（twur），以單元為鍵而非以紀錄為鍵， 因此 297 個帶有它的單元裡，該標記沒有泳道可跨入。另外 262 個單位的全國使用核發與 city's 使照核發 轉換民國年為西元後是同一天 — 同一件事、兩個機關。

5 · 194 個無日期虛擬案的歸屬. 時間軸上沒有位置的節點需要一個明確的家 — 側欄（gutter）或列於圖下方。這是決定，不是預設值。

初版 §6 的「recovery 與 links.taipei 不一致時誰勝出」 已不是待決事項 — Wave 5 的 case-record-join 規格明定 recovery 綁定勝出、 ambiguous-zone 作為來源標記隨行。
