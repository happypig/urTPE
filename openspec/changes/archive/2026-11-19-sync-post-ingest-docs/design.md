# Design: sync-post-ingest-docs

## Context

A maintainer runs a full ingest from an archived PDF, or a rebuild from
`viewer/projects.data.js`. The emitted flow is PDF → raw.tsv → clean.tsv →
merged.tsv → projects.json → viewer payload. The two documentation pages
are authored HTML. They are not regenerated by the CLI. Their measured
figures therefore drift independently of the emitted data.

The existing payload probes contain the domain measurements, but print them
for an operator. The release and coverage generators write reports directly.
The existing recovery command owns the only permitted PDF repair. This
change composes those boundaries; it does not create a second pipeline.

## Goals / Non-Goals

**Goals:**

- Derive all synchronised figures from complete local evidence.
- Make stale documentation a failing, read-only check.
- Offer one bounded post-ingest command with a safe check-only mode.
- Refresh every requested dependent artifact only after local success.

**Non-Goals:**

- No automatic acquisition, scheduled-task changes, commit, push or deploy.
- No new parsing, recovery, identity or portal-discovery rules.
- No full regeneration of the two hand-written bilingual pages.
- No rewriting of dated historical examples into current facts.
- No repair of source-data defects by post-processing emitted JSON.

## Decisions

### D1 — Mark measured regions; preserve the authored document

Each current fact gets a `data-doc-field` attribute on a containing element.
The replacement content is a bilingual pair generated by a pure renderer.
Simple numeric cells use one `data-doc-field` per value. Complex paragraphs
use a marked block whose complete en/zh content is rendered together.

The two scripts are:

```text
python scripts/sync_etl_process.py [--check]
python scripts/sync_domain_model.py [--check]
```

Write mode renders the complete candidate before replacing a file. Check
mode compares the candidate with the file and reports differing field ids.
The scripts never rewrite unrelated bytes. A duplicate or absent required
marker aborts that script. Tests use small HTML fixtures, so they do not
depend on today's payload numbers.

**Alternative rejected:** regex-replacing old numbers. A number such as 30
can be current, historical, or illustrative. Its value does not identify
its meaning.

### D2 — Turn the measurement probes into reusable adapters

`probe_tab2_numbers.py` exposes a pure `measure_payload(doc)` function. Its
existing command prints the same result for operators. The lane function is
corrected for the historical 事業換計畫 typo before lane classification, the
same known error the cleanser repairs; its no-lane samples are not used as
a population measurement.

`probe_tab1_numbers.js` emits a JSON measurement object when called with
`--json`, in addition to its existing human-readable output. The Python
adapter invokes this script through Node and validates required fields and
finite counts. It uses the real `buildConstructionChain`, not a second
implementation. Missing Node, malformed JSON or a viewer API change fails
synchronization rather than inventing a value.

The current §5 table and the current-measurement prose in §2/§4 use these
facts. The six explicitly un-reproducible historical group figures remain
in their historical table, unchanged. The source note distinguishes them
from the current pass.

### D3 — Measure the ETL page from all local artifacts

A shared `scripts/doc_measurements.py` loads the payload and related local
files. It computes record/project counts, date span, flagged nodes, distinct
projects containing flagged nodes, recovered rows, multi-record proportion,
and page/module/cache counts where the source files exist. The live ledger
count is read from `data/review_report.txt`; this avoids parsing a JSONL
ledger whose schema may gain new correction kinds.

The page's schematic values remain examples. Its header, schema counts and
illustrated dataset badge show the measured current values. The operational
procedure gains `--recover-truncated` and the new post-ingest command.
The stale test count is collected with `pytest --collect-only -q` and the
page records that count as of the generation date. The full suite is not
silently run as a substitute for collection.

The initial measured corpus is the complete 2026-11-12 payload: 1,448
records and 676 projects. The earlier 2026-10-28 sample is not reused.

### D4 — Verify in layers, repair only a named cause

`post_ingest_check.py` calls pure checks first:

1. Required input files exist and parse.
2. TSV recno sets and graph node recnos form the same total, disjoint
   partition. Raw 編號 maps to the `recno` column in later TSVs.
3. The graph document and viewer payload agree in schema, counts,
   publication date, project identities, nodes and edges. A formatting-only
   difference is not a data defect.
4. The configured count, deployment artifact list and bilingual doc
   contracts pass their existing focused tests.
5. `node scripts/viewer_smoke.js` and
   `python scripts/baseline_silent_failures.py` run as commands and both
   their exit status and expected success output are checked.

Named truncation exclusions are read from `data/review_report.txt`, not
from raw-cell inference. When present, recovery is attempted once through
`python -m urtpe.cli <archived-pdf> -o data --viewer viewer --links
--recover-truncated`. The PDF is chosen through the archive index and its
recorded content hash where available; an ambiguous match is a refusal.
Any non-zero exit stops processing. Residual rows still stop processing.

A viewer/graph mismatch without a PDF exclusion permits one existing
`--from-js` rebuild, with the current payload as input and link discovery
enabled. Any other partition defect stops with named recnos. There is no
retry loop and no bypass flag. A single successful recheck follows a repair.

`--check-only` performs the same local checks and documentation check mode,
but never repairs or generates. Its output explicitly reports stale facts
instead of claiming the whole pipeline is healthy.

### D5 — Generate dependent reports only after local success

The successful command runs the two sync scripts for
`docs/etl_process.html` and `docs/domain-model.html`, then
`release_diff_report.py` for `docs/release-diff.html`, then
`coverage_report.py` for `docs/coverage-report.html`. Before coverage
generation it copies the newest archived `p168-*.json` snapshot, selected
from `p168_state.json` and verified against its content hash, into
`data/p168_all.json`. This is the existing poller's acquisition output; no
new live enumeration is added.

`p168_header_pass.json` is not silently treated as current. The coverage
report labels the header scan with its file timestamp and counts the
currently missing cases it actually covers. It stops making arithmetic
claims about cases that were never scanned. A missing header scan is
explicitly partial evidence, not proof that every unlinked case is pending.

`openspec/config.yaml` has one marked current-dataset sentence. The sync
adapter updates its approval count and date span; the test
`test_the_recorded_record_count_matches_the_emitted_payload` verifies it.
Historical prose elsewhere in configuration is not changed by number.

The command prints generated/changed/unchanged paths and never invokes git.
A maintainer reviews and publishes explicitly. After a publish,
`check_deploy.py` is the independent network verification.

### D6 — Deploy the ETL page under the existing artifact contract

Add `docs/etl_process.html` to `viewer/deploy.json`. Add its presence to the
offline deployment tests. The deployment requirement delta carries every
existing scenario verbatim and adds one ETL scenario.

## Risks / Trade-offs

- **[Memory]** A full payload measurement and a full release re-read are
  expensive in this session. → Keep only one payload document in memory per
  process; run subprocesses sequentially; avoid the stalled PowerShell
  wrapper; use bounded Bash foreground commands.
- **[Markers]** Adding a marker changes generated documentation bytes even
  when numbers do not change. → The one-time migration is explicit and
  later writes are stable.
- **[Freshness]** Report generation time is not portal evidence time. →
  Label the 168 snapshot and header scan separately; do not infer unmeasured
  cases.
- **[Refusal]** Rebuilding an already-invalid payload can propagate it. →
  Partition defects other than named truncation stop before `--from-js`.
- **[Scope]** A documentation generator can accidentally rewrite historical
  findings. → Only marked regions are mutable; historical values remain in
  tests as preservation fixtures.

## Migration Plan

1. Add pure measurements, markers and failing tests.
2. Generate both documentation pages once and inspect their diffs.
3. Add the post-ingest orchestration and coverage-input bound.
4. Run focused tests, the full offline suite, both sync check modes and the
   real post-ingest command.
5. Review only the owned generated files, then publish explicitly and run
   `check_deploy.py`.

Rollback removes the scripts and markers and restores the two HTML pages;
no archive, correction ledger, pipeline cache or deployed schema changes.
