## Why

The release-diff report (`docs/release-diff.html`) answers "why does the project
count differ between two PDF releases?", and it does so from a reader's
perspective — but it is unreachable. It sits in `docs/`, it is not in the
published artifact list, and nothing links to it from the site a reader
actually visits. The answer exists and cannot be found.

The site also has no way to reach a gazette PDF. The report's 各版公報 table
names each release and the archive copy it was read from, but the archive lives
outside the repository (`D:\project\urtpe-gazettes\`) and is not reachable from
a browser. A reader who wants the document the city published has no link.

And the report is stale the moment the next gazette arrives. It is generated by
hand (`scripts/release_diff_report.py`), so a new publication is added to the
archive and nothing re-derives it. The task that watches for new gazettes
(`urtpe-poll`, weekly Monday 06:30) acquires them and stops there — it never
regenerates the report and never publishes anything. The site it keeps alive
is therefore as stale as the last manual run.

Three gaps, one cause: the report and the site are two separate things that
nothing connects.

**The publisher's URL is not a stable per-release address.** Measured
2026-11-06: the gazette page carries exactly one PDF link and the city
repoints it on every publication, so the live URL serves the newest gazette
only. But a *version-specific* URL stays durable once it is known — the
2026-10-15 URL recorded in `docs/urotpe_api_vs_pdf.md`
(`…/relfile/18558/10496/1d9657b0-….pdf`) still serves the 2026-10-15 document
(a different SHA-256 from the current one), while a fabricated UUID path
answers 404. So a release *can* carry its own link, provided the URL that
served it was recorded when it was fetched. Only one such URL survives in the
whole repository, because the poller records the digest and the publisher's
stamp but not the URL it fetched from.

## What Changes

- **The release-diff report becomes a published page.** `docs/release-diff.html`
  joins `viewer/deploy.json`'s artifact list, so `scripts/check_deploy.py`
  compares its served bytes against the committed blob like every other
  artifact. A stale report becomes detectable instead of silent.

- **The viewer links to the report.** A `歷次公報差異` link in the viewer's
  header, and a back link in the report's own header. Both are plain
  relative links between two static files, so they work from `file://` and
  from the published site alike.

- **Each release links to the document the city published.** The 各版公報
  table's newest row links to the live publisher PDF, with the publisher's
  資料更新 stamp beside it. Older rows link to the version-specific URL that
  served that release, **when one is known**; a release with no recorded URL
  says so in words rather than linking to a document that is not the one its
  row is about. A link to the wrong gazette is worse than no link.

- **The poller records the URL it fetched from.** The archive index gains a
  `publisher_url` field, so a version-specific URL is captured at the moment it
  serves a document and is durable thereafter. From this change forward every
  release accumulates its own link; the releases already held keep the
  behaviour they have today, and the report says which is which.

- **The report is regenerated and published after the poller.** The `urtpe-poll`
  task gains a third action that regenerates the report, commits it and the
  viewer data it reflects, and pushes to `main`, which is the branch GitHub
  Pages publishes from.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `gazette-cadence`: the archive index records the publisher URL a document was
  fetched from; the unattended check may regenerate and publish the
  release-diff report, and the boundary between "acquisition" and "ingestion"
  is restated to include publication.
- `gazette-archival`: an index entry records the URL the document was fetched
  from, so a version-specific publisher address is not lost when the city
  repoints its link.
- `deployment-verification`: the published artifact list covers the
  release-diff page, so its served bytes are compared against the committed
  build like every other artifact.
- `viewer-related-links`: the viewer's header links to the release-diff page,
  and the release-diff page links back.

## Impact

- Code: `urtpe/poller.py` (record the publisher URL; a publication step),
  `urtpe/archive.py` (the `publisher_url` index field), `scripts/release_diff.py`
  and `scripts/release_diff_report.py` (the links and the back link),
  `scripts/publish_release_diff.py` (new: regenerate, commit, push),
  `viewer/index.html` (the header link), `viewer/deploy.json` (the artifact
  list).
- Live state: the archive index gains a field per entry; the archive is
  append-only, so older entries carry no URL and keep the current behaviour.
- Scheduled work: the `urtpe-poll` Windows task gains an action. It runs
  weekly, unattended, and pushes to `main`.
- Not gated on POC findings: the link threshold (0.7) and the merge weights
  are unchanged. The measurement that shaped the URL design — one live link,
  durable version-specific links — is in the design's Context section.
