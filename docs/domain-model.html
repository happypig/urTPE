§4TaipeiCase 北市案件

Proposed — not implemented. 提案中，尚未實作。

The gazette and the portals do not agree on what a thing is. The gazette counts 核定案件 — one approval. The Taipei portal counts 案 — one application, which can span several approvals. Nothing in the model names that second thing, so it is carried as loose keys. 公報與門戶對「一件事」的定义並不一致。公報計的是核定案件 — 一次核定。 北市門戶計的是案 — 一件申請，可能橫跨多次核定。模型裡沒有為這第二種東西命名， 於是它以零散的 key 形式被攜帶著走。

The asymmetry it costs today · 今天為此付出的代價

virtual case虛擬案
  • orphan_nodes 內的完整物件
  • 11 個欄位，自足
  • 讀一個物件即可畫出
real case真實案
  • 散在四個字典
  • 節點上還留了一份重複
  • 必須 join 四處才畫得出

Drawing a virtual case is reading one object; drawing a real case is joining four. That asymmetry is why the viewer handles them differently — and why 456 progress markers are anchored by a coin-flip: anchoredByCase[cid] = n.recno keeps whichever record was written last, and 343 cases sit on more than one record. 畫一個虛擬案是讀一個物件，畫一個真實案要 join 四處。這個不對稱正是 viewer 對兩者處理方式不同的原因 — 也是 456 個進度標記靠擲硬幣決定錨點的原因： anchoredByCase[cid] = n.recno 留最後寫入的那筆，而有 343 個案掛在不只一筆紀錄上。

Two integrity problems this shape would expose. 這個形狀會暴露出的兩個完整性問題。

20 virtual cases are listed more than once — orphan_nodes holds 969 entries for 949 distinct case ids. And 9 case ids appear both as virtual and as real, so the total is 1,921 or 1,912 depending on which wins. Neither is visible today because the virtual set is a flat list keyed by nothing. 20 個虛擬案被列了不只一次 — orphan_nodes 有 969 筆， 但只有 949 個不同 case id。另有 9 個 case id 同時出現在虛擬與真實兩邊， 所以總數是 1,921 或 1,912，取決於哪一邊採計。今天這兩件事都看不見，因為虛擬集合是一個 沒有鍵的扁平清單。

Three invariants三條不變條件

1 · record_recnos is the only relation between a case and the gazette. record_recnos 是案與公報之間唯一的關係。

Measured: 1,409 bindings; 343 cases cover more than one record (up to 4); 0 records name more than one case. Many-to-one, and must be stored in that direction — never inferred from a shared name or a matching parcel. 量測：1,409 個綁定；343 個案涵蓋不只一筆紀錄（最多 4 筆）；0 筆紀錄掛在不只一個案上。 是一對多，必須以這個方向儲存 — 絕不可從同名或地號相符去反推。

2 · case_name is parsed, never compared. case_name 是用來解析的，不是用來比對的。

It self-declares 段, 首宗地號, 筆數, 階段 and track. That is what separates the 493 groups of cases sharing 段 and 首宗地號 — 365 differ on count or stage, and 128 are identical on both. Comparing the name for equality, or ignoring the parts that differ, collapses those groups. 它自帶段、首宗地號、筆數、階段與 track。正是這些把「段與首宗地號相同」的 493 組案 分開 — 其中 365 組在筆數或階段上不同、128 組則在兩者上都完全相同。用相等去比對案名， 或忽略其中有差異的部分，都會把這些組collapse 掉。

3 · Milestones belong to the case, never to the record. 里程碑屬於案，永遠不屬於紀錄。

The node's flattened copy is a denormalised duplicate, and it is the reason a milestone can be dated two years before the record it is drawn against. 節點上那份扁平副本是非正規化的重複物，也正是某個里程碑會比它所對照的紀錄早兩年的原因。

Two rules that fall out由此導出的兩條規則

Rule規則 Resolves解決
Anchor resolution. When several records carry a case, a milestone attaches to the latest record approved on or before the milestone's date — not the last one iterated. 錨定解析。當一個案掛在不只一筆紀錄上，里程碑應附到 在該里程碑日期當日或之前最近一次核定的那筆紀錄 — 而不是最後被迭代到的那筆。 456 ambiguous markers; 428 resolve, 28 have no prior approval 456 個錨定有歧義的標記；428 可解，28 沒有更早的核定
Discriminator. When several cases share 段 and 首宗地號, separate them by declared count and stage. Where identical on both, attach none and report the group as ambiguous. 判別式。當數個案共享段與首宗地號，以宣告筆數與階段區分。 兩者都相同時一個都不掛，並把該組列為歧義。 the 128 genuinely-identical groups 那 128 組完全相同的案

A wrong attachment is worse than an admitted gap — so where the rule cannot decide, the case stays unattached and the count is reported. 錯誤的掛接比坦承的缺口更糟 — 所以當規則無法判定時，該案保持未掛接，並將數量回報。

Open question待決問題

191 of 949 virtual cases carry no date at all. They are retained today because orphan_nodes holds them, but a class with no position on the time axis needs a stated home — a gutter column, or listed beneath the graph. That is a decision, not a default. 949 個虛擬案中有 191 個完全沒有日期。它們今天被保留下來是因為 orphan_nodes 留著它們，但一個在時間軸上沒有位置的類別需要一個明確的歸屬 — 一個側欄欄位，或是列在圖的下方。這是一個決定，不是一個預設值。

§6Gazette cadence 公報節奏

Acquisition is a separate process from ingestion. A gazette is identified by its content hash, never by a timestamp — the city re-uploads a byte-identical PDF and only advances the stamp on the page. The archive lives outside the repo, so a pipeline run cannot destroy the only copy of a publication. 取得與匯入是兩個分開的過程。公報以內容雜湊辨識，不以時間戳記 — 市政府會重新上傳 位元組完全相同、只更新頁面標記的 PDF。檔案庫位於 repo 之外，因此管線執行不會毀掉某次發行的唯一副本。
